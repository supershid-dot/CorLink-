# Rollback - 016: Workflow Executable Instance Activation

Run `supabase/rollback-workflow-executable-instance-activation.sql` only to remove CAP-002 Phase 2B.2 (executable instance activation) while retaining the approved Phase 1/2/2B.1 workflow foundation, runtime, and executable definition validation.

The rollback is transactional. It restores the exact pre-2B.2 body of `workflow_transition_instance(uuid, text, bigint, uuid, text, text)` (copied verbatim from `supabase/patch-workflow-runtime.sql`, which this patch never edited) and drops the two Phase 2B.2 tables, `workflow_approval_rounds` and `workflow_approval_positions`. It does not use `CASCADE` and does not touch `workflow_definitions`, `workflow_definition_versions`, `workflow_instances`, `workflow_instance_steps`, `workflow_tokens`, `workflow_work_items`, `workflow_events`, `workflow_participants`, the Phase 2B.1 `canonicalize_workflow_definition_payload()` validator, or the 5 public wrapper RPCs (`start_workflow_instance`, `suspend_workflow_instance`, `resume_workflow_instance`, `cancel_workflow_instance`, `complete_workflow_instance`), which this patch never modified.

The rollback unconditionally refuses if any `workflow_approval_rounds` or `workflow_approval_positions` row exists — i.e. if any instance has ever been activated through an approval node. Dropping those tables would irreversibly destroy that round/position history, and docs/60-64 define no compatibility path for representing it afterward. Instances that only ever reached the Start→End special case leave no round/position rows and are otherwise inert once `completed`, so they do not block rollback.

The verified procedure was: build a true pre-2B.2 baseline (Phase 1+2+2B.1 chain, patch never applied) and capture `pg_get_functiondef('workflow_transition_instance(...)')` and its grants; apply the 2B.2 patch; seed one instance through an approval node and confirm rollback refuses with zero partial effect (function definition and table existence unchanged); rebuild a fresh 2B.2 chain with no activation history and confirm rollback succeeds; compare the restored function definition and grants against the true pre-2B.2 baseline (byte-exact and grant-exact match, both confirmed); run `supabase/validate-workflow-executable-instance-activation-rollback.sql`; reapply `supabase/patch-workflow-executable-instance-activation.sql`; rerun the structural validator and the 40-scenario behavioral and 6-scenario RLS suites (all passing).
